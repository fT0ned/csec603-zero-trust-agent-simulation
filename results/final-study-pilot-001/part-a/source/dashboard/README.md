# Local research console

The console runs at <http://127.0.0.1:8765>. It orchestrates the same runner and analysis commands as the command line. Collection writes preserved batch directories under `results/`; console reset never deletes those directories.

1. Follow the repository setup instructions and bring up the testbed. From the repository root, launch `.venv\Scripts\python.exe -m dashboard` on Windows, or `.venv/bin/python -m dashboard` on Linux.
2. Open <http://127.0.0.1:8765> and select **Check again**. Docker, provider-key presence, established spending limit, and pre-run-freeze status appear independently. Presence checks do not establish provider credit or testbed health; the runner performs collection checks.
3. Begin with **Scripted · control check / Engineering verification**. Select conditions, scenarios, repeat count, and timing. Press **Start experiment**. Scripted observations are labelled as control checks throughout the interface and are never presented as real LLM findings.
4. Select a batch in **Collection history**. Follow its collection status, recorded trial count, and `progress.json`. Click a trial in **Evidence explorer** to load its summary and rotated action/audit/model traces. Select an analysis artifact to inspect tables or plots; compressed `.jsonl.gz` traces are decoded for display. The exact filenames available depend on the runner output.
5. Use **Compare conditions** for descriptive counts from the selected batch. This view keeps scenario, lifetime, revocation mode, agent mode, and collection phase distinct. Use the generated analysis files for confidence intervals, paired comparisons, and hypothesis interpretation.
6. Download **Export CSV**, **Export JSON**, or **Reproducibility bundle**. A bundle requires collection to finish or be cancelled, includes sanitized evidence and executable source, and supplies SHA-256 hashes of exported bytes. Sanitization changes exported credential fields; original raw files remain unchanged locally. Bundles prefer the preserved collection-time `source/` snapshot. Additional support files appear under `export-time-extras/`; legacy batches without a source snapshot explicitly label their export-time fallback. Use collection commit/freeze metadata to identify the original version. Large ZIPs are staged on disk under ignored `.runtime/exports`, streamed to the browser, and removed after the response. Compressed traces remain valid sanitized gzip streams in the ZIP.
7. **Cancel collection** stops the runner process tree and retains partial evidence. **Reset console** clears the selection/form after active collection ends. Each new runner trial resets controlled testbed state; reset is never a deletion mechanism for prior measurements.
8. For paid pilot runs, put `DEEPSEEK_API_KEY` for DeepSeek models (or `OPENAI_API_KEY` for OpenAI models) and `STUDY_BUDGET_USD` in the untracked repository `.env`, restart the dashboard, and choose **Real LLM · provider API**. Supply the validated model identifier and a positive batch cap. The default is `deepseek-flash`; provider responses and model metadata are preserved, and the runner does not silently substitute a provider or model. The runner enforces the established total limit using the persisted `.runtime/spend.sqlite` ledger; do not reset or delete that ledger to bypass spending controls. Full studies additionally require the approved pilot, frozen design, and runner checks. A dashboard cap does not authorize exceeding the established study limit.

The backend listens only on loopback. It rejects non-loopback Host headers, cross-origin mutations, and paths outside the selected batch. API documentation is at <http://127.0.0.1:8765/api/docs>. Never expose this local research console through a public tunnel.

On dashboard restart, unfinished jobs are marked `interrupted`; inspect their preserved evidence before scheduling a replacement. Do not silently merge partial, scripted, pilot, and full-study observations.

Batches launched from the command line are discovered from their existing manifest and configuration, then observed read-only. Their progress appears alongside dashboard-launched collections, with the original mode and phase. Dashboard restart does not label a CLI collection interrupted. Its harness-written `batch-status.json` determines completion; analysis availability is reported separately. Stop an external collection in its original terminal. The dashboard rejects external cancellation and prevents a competing dashboard collection while CLI collection is active. It does not create `job.json` or alter the external manifest, source snapshot, or raw observations.

## Browser and API verification

`python -m pytest tests/test_dashboard.py -q` verifies the collection/analysis lifecycle, retained raw evidence, sanitized export bundle, path/host/origin boundaries, uncredentialed and unfrozen-study rejection, cancellation, single-active-batch handling, and restart recovery. These tests substitute a local runner fixture to isolate dashboard behavior; they do not establish security-control or LLM research findings. The repository handoff records the separate browser-to-real-testbed verification.

Replay handoff timing uses the configured `theft_delay_seconds` (default 120 seconds, allowed range 1–1800 seconds), measured from credential receipt rather than variable model completion. Load the repository preset to use the frozen study timing and concurrency; review these fields before collection.


## Host monitoring update after study-freeze-v1

The host dashboard caches compact UI projections by each summary's nanosecond modification time and byte size. It retains only fields needed by the interface and a within-run latency median, discarding latency arrays and other raw detail after the first read or a changed file. `/runs` returns these compact projections; explicit CSV/JSON exports and trace inspection still read complete sanitized raw summaries. The comparison latency is the median across per-run medians in milliseconds, matching the analysis unit of independent runs. Unchanged status/completion counters no longer trigger repeated evidence reloads; active collection progress remains visible through the jobs endpoint.

This is a host UI/monitoring-only change after the collection freeze. It does not modify collection code, frozen design, collected source snapshots, raw observations, or analysis. A reproducibility export continues to prioritize its collection-time source; export-time support files may reflect this newer dashboard revision.

External CLI batches whose completion marker records `interrupted: true` display **interrupted** with the preserved operator reason. Unfinished trial summaries remain unchanged; they are not relabelled as completed or counted as infrastructure failures by the dashboard.


## Post-collection release after study-002

The original study-002 dashboard export QA is preserved in `docs/verification/study002-browser-export.md` and its companion JSON/screenshots. Its 17,333 sealed raw members included one `checkpoint.json.tmp` omitted by the original suffix filter. The subsequent host dashboard permits only that exact filename under a run directory when it is a bounded JSON object and its SHA-256 matches the exact member listed in that run's raw manifest. Arbitrary/unsealed/changed temporary files remain rejected; exported checkpoint JSON is credential-redacted while raw bytes remain unchanged.

Collection completion and data quality are displayed separately. A failed immutable `validation.json` produces a prominent warning; completion counts describe distinct completed units, with retained failed attempts labelled separately. All attempts remain available in traces and full CSV/JSON exports. Historical study-002 remains quality-failed; this presentation correction does not validate or repair its timing observations.

The configuration form accepts `system_prompt_profile` (`original-v1` or `neutral-v1`), optional `protocol_id`, and optional `study_kind`. Repository presets include the exploratory neutral-prompt pilot and deterministic enforcement stress. Selected-batch provenance identifies the profile/protocol/study kind; historical batches without these fields explicitly show their legacy defaults. These are separate protocols and must not be pooled. Frozen original experiments must be reproduced with their preserved configuration and source; an edited configuration requires its own applicable pre-run freeze.

These host-only corrections were made after original collection. The original tags, collected source snapshots, configuration, raw evidence, and failed validation remain preserved. Restart this dashboard revision only at an idle collection boundary; a running server continues its loaded backend until restart.


Gzip export preserves exact original compressed bytes when a bounded scan of every JSONL record finds no required redaction. If redaction is necessary, the archive sanitizes/recompresses that trace and lists the original/exported hashes in `EXPORT_PROVENANCE.json`. Original raw manifests remain preserved; altered sealed members cannot pass those original seals. The provenance also lists missing sealed members and never claims the exporter performed raw verification. Extract an unchanged bundle and run the preserved analysis CLI's `--verify-raw` check before claiming reproducibility. The original study-002 archive predates this correction and recompressed clean gzip streams; its exported SHA-256 checksums passed, but those bytes cannot satisfy the original gzip seals.


Quality presentation aggregates the preserved `validation.json`, collector `quality.json`, and additive `quality-adjudication.json`. Any failed assessment vetoes passing clock or consistency checks; unreadable or incomplete assessments prevent a displayed pass. Each assessment retains its path, scope, errors, and byte SHA-256. Sibling semantic reviews are accepted only from a contained results subdirectory's `quality-adjudication.json` with `collection_id` equal to the target batch directory ID and `collection_path` equal to its exact repository-relative path, for example `results/study-002`. Absolute, traversing, mismatched and escaping bindings cannot approve or veto a different collection. Existing collected files are never rewritten. Full CSV/JSON rows label derived review context with `_batch_quality_*` fields. Bundle provenance records aggregate quality, and bound sibling reviews are copied under `results/external-quality/` as additive evidence outside sealed run folders.
