## Additional infrastructure instrumentation

The wrapper adds monitoring outside the frozen SUT/run implementation. This is an explicit engineering amendment, with possible monitoring overhead; it does not silently claim identical infrastructure load. There are31 submitted workers versus the original configured32 because the repair subset contains31 units. The untouched configuration/summary metadata still records the frozen maximum32; actual dispatch count31 is recorded here and in the repair manifest/status.

At execution, preflight checks deployed server/client/tool bytes, genuine SPIRE agent/server health, host→gateway/PA HTTP clock brackets and host→attacker Docker clock brackets. It refuses to start while PA reports active tasks, avoiding overlap with another collection. Execution uses the existing idle-sleep prevention context; it changes no Windows clock, NTP settings or power plan.

A dedicated monitor samples host epoch and monotonic clocks, two HTTP health clocks, and one attacker-container epoch/monotonic reading per cycle; it waits approximately5 seconds between cycles. Docker query timeout is10 seconds and each HTTP timeout5 seconds. Windows Kernel-General event1 and Time-Service logs are refreshed approximately every30 seconds, with a20-second query timeout. Thus there is at most one Docker clock exec per cycle, no tight polling, and actual sample cost/gaps remain measured rather than assumed. Monitoring delay beyond the prespecified15-second maximum intersample gap fails quality. Read-only Windows queries distinguish no events from access/query failures and capture exact XML; no secret/config output is requested.

The separately declared engineering quality gates are:

1. Exactly31 completed replacement units, with one-to-one original links and no automatic retries.
2. The frozen absolute handoff error ≤1 second for every replacement; missing values fail.
3. No backward adjacent client probe timestamp in any replacement stream, scanning the initial `probes.jsonl.gz` followed by every numbered rotated `probes*.jsonl.gz`, carrying the previous timestamp across file boundaries. Focused temporary fixtures verify reversal inside a later rotation and across a rotation boundary.
4. Every measured clock bracket has absolute offset endpoint bound ≤1 second; host epoch-versus-monotonic change during a sample ≤.05 seconds; no monitoring gap >15 seconds or monitoring/query error.
5. No Windows clock-step event of absolute magnitude ≥50ms during the captured repair interval. This50ms threshold is a new conservative engineering veto, declared before repair, not a change to the original±1-second handoff criterion.
6. Preserved raw seals verify. Batch status has no unexpected errors, including failure of the final Windows-event capture; a final-query failure cannot pass using an older event snapshot. `quality.json` reports repair-subset quality only; it cannot confer complete-study eligibility. Dashboard status exposes `planned=31` and remaining noncompleted/unexpected failures explicitly.

Samples cannot prove perfect clock continuity between readings. No retroactive clock correction is applied to original traces. A monitor failure flags the affected repair evidence and never triggers an outcome-driven extra attempt. The frozen model alias remains mutable and provider generation has no deterministic sampled seed; matching harness seeds/fixtures does not reproduce the same model response. Later collection time and31-versus32 workers remain amendment limitations.
