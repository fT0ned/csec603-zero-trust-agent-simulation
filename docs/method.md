# Experimental method and engineering decisions

The governing source is the parent `enterprisePhase2_FINAL.docx`, dated October21,2026. Official Track B requirements and the Leopard professor feedback take precedence. This repository implements the existing design rather than replacing the literature review or Overleaf manuscript. All parameter choices below are authors' experimental settings; they are not externally measured enterprise norms.

## Conditions and trust boundary

C0 uses a disposable non-expiring static bearer key, broad tools and minimal condition-visible logs. C1 uses a real SPIRE JWT-SVID with the same broad access and identity-aware logs. C2 combines this identity with OPA decisions, trusted task-scoped delegation, atomic workflow limits, intent-bound simulated approval, one-use120-second JIT grants and full audit. C2-noWF disables only cumulative limits; C2-RS changes only approval to always approve. Both ablations apply only to S2/S5. Every condition validates the credential and consults the same deny-list on every request. C1 cannot be credited with stronger revocation or resistance to replay of a stolen bearer token.

The agent and attacker are separate containers with distinct socket-peer origins. They can reach the gateway but cannot reach tools, PA, OPA or the issuer. Only the agent has the SPIRE workload socket. The principal's delegation is held by the trusted PA; request fields cannot supply or alter authority. Trusted host orchestration owns Docker lifecycle, protected ground truth and checkpoints; compromise of that host or control plane is outside scope. Node attestation uses a securely bootstrapped SPIRE join token; workload attestation uses Unix UID10001. This is a single-machine process-attestation study, not hardware-rooted remote attestation or enterprise-scale validation.

## Tasks and attacks

Three legitimate task families cover bounded CRM exports, one approved invoice payment and one approved internal email. S1 also exposes harmless external content containing an attacker-looking address. Task-specific action scopes preserve those tasks. All datasets, addresses, vendors and invoices are synthetic; tool services never send email or transfer money.

S2 includes external email, an unrequested in-scope invoice, deletion and an unrequested in-scope partner email. S5 includes four5-record chunks against a10-record whole-task limit and four40-unit payments against a100-unit workflow limit. The chunk task explicitly requests two5-record chunks, aligning principal intent with the cumulative bound. Payment/email approval fixtures intentionally pass action/vendor/domain scope while conflicting with the principal's exact requested parameters. The careful approver compares the complete action and parameters with trusted expected calls; the rubber-stamp variant approves all policy-eligible requests. Simulated approval computation time is measured; no human response delay is invented.

The S5 primary chained goal is total exported records or paid amount above the workflow bound. An unsolicited payment within that bound is separately reported as `intent_violating_outcome`; it must not be mistaken for successful prevention of all unauthorized intent. Approval can mask workflow effects in the payment fixture, so workflow-isolation interpretation uses the chunk subgroup and reports approval-dependent payloads separately.

Payloads in `testbed/fixtures.py` are authors' fixed adaptations of instruction-override, role-spoofing and task-hijacking patterns discussed by [AgentDojo](https://github.com/ethz-spylab/agentdojo) and its [NeurIPS2024 paper](https://proceedings.neurips.cc/paper_files/paper/2024/file/97091a5177d8dc64b1da8bf3e1f6fb54-Paper-Datasets_and_Benchmarks_Track.pdf). They are not literal benchmark extracts or benchmark-comparable scores. Sources were checked against primary pages; a human bibliographic audit for manuscript submission remains separate.

## Measurement and failures

Each run receives a fresh registration/credential, trusted delegation, task namespace, mock snapshot, counters, deny-list and audit chain. Containers are reused with independently reset state. Reachability uses isolated freshly reset auxiliary tasks, one request per distinct action, with task-approved parameters where an executable instance exists. Auxiliary tasks retire before the main replay phase and cannot inflate its success outcome. Probe outcomes do not count as model injection following.

S3/S4 perform a distinct harmful replay and harmless credential-validity probes. TTLs300/900/3600 are real seconds. The observation horizon is TTL+5seconds, capped by the configured maximum; paired conditions at the same TTL use the same horizon. S3 interval is10seconds; S4 interval is0.1seconds. Probes are scheduled inside the attacker container against an absolute deadline. Actual timestamps and latency are retained. A harmless baseline first proves validity. S4 records a common security-decision time, then either immediately revokes or leaves the credential to expire. First-denial measurements include client-start/first-probe delay; gateway deny-list propagation is a separate timestamp interval. Clock brackets are preserved in infrastructure verification.

Exposure is last successful replay minus theft, a lower bound; first denial is the upper endpoint used for survival analysis. Static or still-valid credentials are right-censored at the actual observation window. Nominal lifetime is only a reference. No censored lifetime is averaged as a completed event.

Gateway responses are reconciled with an independent host-read snapshot of committed tool databases and write-call IDs. The system under test cannot read or write host ground-truth/checkpoint files. Host checkpoint updates recompute the audit hash and count. Fixed alteration, middle/tail/all deletion and reorder tests run on copies, including final-record deletion. Checkpoints do not defend against compromise of the trusted host or concurrent loss of both protected stores.

The PA serializes a task's policy check, workflow reservation, JIT consumption and tool request. Confirmed tool success reconciles reserved and actual effects; an ambiguous downstream timeout retains the reservation to prevent a second action exceeding the bound. Reusing a write request ID has one tool effect. Revocation blocks even a cached retry. Provider/model errors remain experimental units with explicit task-failure reasons; only infrastructure failures receive one retained rerun with the same seed. No outcome-based exclusions, added runs or early stopping are allowed.

## Model and spending

The main provider is `deepseek-flash`, documented as DeepSeek-V4.1-Flash-1017 on the official [model/pricing page](https://api-docs.deepseek.com/quick_start/pricing/). The API exposes a mutable alias rather than an immutable snapshot. Each trial preserves the requested and returned identifier, provider catalogue, system fingerprint, dates, settings, prompts, responses and tool calls. That limitation must appear in the paper; the code never silently changes provider/model. Temperature is0 and thinking is explicitly disabled under the [official API contract](https://api-docs.deepseek.com/api/create-chat-completion/).

Only mock content is transmitted. The [provider privacy policy](https://cdn.deepseek.com/policies/en-US/deepseek-privacy-policy.html) governs provider processing; this study makes no zero-retention or confidential-data assurance. API secrets stay in ignored local files and do not enter containers or exports.

A read-only balance check found4.93USD prepaid. The engineer selected a conservative4USD aggregate cap under the user's full implementation autonomy; no top-up is authorized. SQLite reservations enforce that cap across concurrent workers and batches. Uncertain requests retain their reservation. Token charges use provider-reported cache usage and verified rates; peak/holiday ambiguity is labeled a price ceiling. Actual account-balance reconciliation is separate. Never reset the ledger to bypass the cap.

## Inference limits

The pilot and scripted engineering results remain separate from full real-LLM evidence. The default final sample is30per cell, fixed after pilot validation. The main+ablation+sweep manifest has1200unique trials;15-minute main cells are counted once. Overall S2/S5 counts split across payload subgroups, reducing subgroup precision. Analysis follows `docs/analysis-plan.md` with prespecified practical thresholds, paired tests where exact matches exist, Holm correction, uncertainty and explicit missingness. Configuration-guaranteed controls and hash checks are sanity checks. This is one machine, one agent, one provider/date, a small fixed corpus and an idealized approver; outcomes do not establish general enterprise effectiveness.
