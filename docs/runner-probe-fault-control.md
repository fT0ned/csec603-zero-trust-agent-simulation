# Prepared host-runner controlled-fault verification

**Prepared only; do not execute before the lead clears postcollection verification and the current application image is deployed.** The [helper](../scripts/verify_runner_probe_failure.py) defaults to a preparation-only message. It creates no Docker query, run namespace or fault without `--execute`.

After clearance, run `.venv/Scripts/python.exe -m scripts.verify_runner_probe_failure --execute`. The helper first requires zero active PA tasks, then compares the actual attacker/PA image bytes for current client, classifier, service and runner modules against the host. It refuses a stale research image. It creates a unique `results/qa-runner-probe-failure-<UTC>-<random>/` engineering collection containing one actual C0/S4/expiry scripted run. Observation is configured2seconds; engineering has zero theft delay. This is a controlled error-path test with no LLM/provider call, not a research observation or replacement trial.

The sole host monkeypatch wraps `runner.container_request`. It calls the real successful attacker baseline `files.read(brief)` first and returns that original response unchanged. Before returning it, the wrapper injects one explicitly authorized private-tool fault:

1. Require a fresh helper-owned batch with exactly one new running `r<32hex>` folder whose condition/scenario/seed/mode/phase match this engineering case. Require its start timestamp to follow helper start and its real baseline audit credential/request IDs to match the owned identity/request.
2. Send only that run ID, baseline request ID, expected synthetic brief-content hash and helper batch name to the private files container over Docker exec stdin. Bearer tokens and administrator secrets are excluded.
3. In a SQLite `BEGIN IMMEDIATE` transaction, use parameterized queries for that exact run and committed baseline request. Check the baseline fingerprint is precisely `files.read` with `path=brief`, its response was successful, and its returned content matches the current brief/hash.
4. Remove only the `brief` key from that run's state with a parameterized compare-and-swap `UPDATE ... WHERE run_id=? AND state=?`; require exactly one changed row. Leave all other fields, run namespaces, call rows, policy, PA audit and source untouched. Save the complete synthetic before/after state, hashes and mutation receipt outside the sealed run folder. No additional PA audit action is introduced.

The real stream then encounters a real missing-file tool failure while credential authorization remains allowed. Acceptance requires the actual deployed client flag `measurement_failure` retained in the failed-probe record, independently recomputed host `probe_measurement_error`, expected infrastructure-failure unit status, null event/first-denial fields, and the actual allowed=true/tool_error action/audit. The audit immediately follows the real baseline with no synthetic intermediate PA action; its full chain must match the protected checkpoint. Verify all raw seals and independently read the private tool state after retirement. A fresh PA health response must confirm `active_runs=0`, in addition to absence of a retirement-error file. The shared spend-ledger hash must remain unchanged. A passed helper means it correctly observed the **expected failed engineering unit**, never that the unit is a successful research trial.

The helper never retries, restores a global snapshot or edits original/repair evidence. `run_one` retires its own task; the controlled namespace's missing brief remains preserved as fault evidence in the durable private tool state. Verification output and independent evidence live outside its sealed raw folder. Any unexpected exception produces a failed verification record and is not converted into a pass.

Six offline SQLite-fixture tests passed before execution was authorized: exactly one owned row changes, unrelated state/call rows remain unchanged, malformed/injected run IDs and non-helper batch names are rejected, missing baseline/content mismatch roll back, and a non-brief baseline cannot authorize mutation. These fixtures make no Docker/provider calls. Current client/runner live behavior and actual controlled-fault acceptance remain unverified until the postcollection run is performed.
