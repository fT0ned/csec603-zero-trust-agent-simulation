The paper is for CSEC.603.600 Enterprise Security at RIT Dubai (Dr. Belal Ali), simulation-based research track, IEEE double-column format:

"Who Authorized This Agent? Identity, Delegation and Accountability in Zero Trust for Agentic AI"



Core argument: identity authenticity does not prove action legitimacy. Possession, delegated authority and accountability fail separately, and each needs a different enforcement response. This is the Possession–Authority–Accountability (PAA) model. All controls are tested under assume-breach. This is not prompt-injection research.



Existing frozen study: `results/final-study-001`, 3,090 runs, DeepSeek Flash, temperature 0.

- Part A: scenarios S1–S5.

- Part B: out-of-authority objectives.

- Part C: stolen-token replay against sender binding and auto-suspension.



Conditions:

- C0: static key.

- C1: SPIRE JWT-SVID.

- C2: OPA policy with task-scoped delegation, workflow limits, careful approval, one-use just-in-time (JIT) grants and hash-chained audit.

- C2-noWF and C2-RS: ablations.

- C2-AS: auto-suspension.

- C3: DPoP-style binding.

- C3-AS: binding plus auto-suspension.



Key results:

- A static key stayed valid for the whole observation window.

- A JWT-SVID stayed usable until it expired.

- C3, C2-AS and C3-AS refused the stolen token on its first use.

- Auto-suspension also locked out the legitimate agent in 30/30 runs.

- C2 blocked 0/120 out-of-authority actions get through, against 120/120 for C0 and C1.

- Impersonation attribution was 100% for the C2 family and 0% for C0 and C1.

- The injection was followed in 0/300 runs.

## 1b. Professor's Report 2 feedback (address all of it)

Minor issues:

- The literature synthesis is too dense.

- Impersonation was tested and attributed, but coercion was not, because the LLM never followed an injection.



Recommended improvements, in priority order:

1. Make coercion actually succeed under the baseline. Measure coercion success rate, prevention and containment under C2/C3, whether the system tells a coerced legitimate agent apart from an impersonator, attribution accuracy, and remediation decision accuracy.

2. Move beyond the single-host testbed: agent → workload identity → remote PEP → policy service → several applications. Measure latency, revocation propagation, failure behaviour and availability across network boundaries.

3. Implement multi-hop delegation (human → Agent A → Agent B → tool). Test whether authority attenuates at each hop, whether provenance survives each hop, and whether the PDP can reconstruct who authorized whom.

4. Formalize PAA: inputs → trust state → failure classification → enforcement response → recovery. Use invariants: failed possession → refuse the request; compromised bearer token → revoke it; valid identity with invalid authority → deny the action and keep the identity; accountability failure → escalate or contain based on confidence. Then compare PAA experimentally against uniform "suspend everything".

5. Replace simulated approval with a realistic model: delay, timeout, abandonment, fatigue, rubber-stamping, false approvals and denials.

6. Implement full RFC 9449 DPoP, or rename C3 as an experimental proof-of-possession scheme. Ideally also compare against mTLS-bound identity.

7. Replicate across at least 3 model families: commercial frontier, an alternative commercial model, and a local open-weight model. The aim is stable control conclusions, not ranking the models.

8. Increase workload diversity (finance, CRM, data export, privileged admin, SaaS APIs, different authority structures) rather than run count.

9. Measure operational costs: policy administration effort, rule count and complexity, identity lifecycle overhead, PEP/PDP resource use, audit storage, recovery time after suspension, availability impact.

10. Archive formally with a DOI (Zenodo, OSF or a GitHub release) and one-command reproduction.

11. Novelty is not the mechanisms. It is "a unified controlled evaluation of possession, delegated authority and accountable attribution for agentic AI, with failure-specific Zero Trust response selection".

12. Tighten the paper around three contributions: experimental evidence → PAA model → enterprise implications.



The professor's must-haves are 1 (coercion and attribution), 3 (multi-hop) and 2/7 (distributed or multi-model validation of PAA).
