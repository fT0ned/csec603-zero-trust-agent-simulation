## Prospective endpoint fix review

The current main source shares `testbed.probe.classify_probe` between the container stream client and host runner. An observed credential-denial event requires HTTP200, `outcome=denied`, `allowed=false` and an exact validator reason of `revoked` or `invalid or expired JWT-SVID`. Tool errors, infrastructure errors, transport failures and policy denials fail measurement explicitly. The combined JWT reason establishes observed rejection, not proof of exact expiry. Missing/ambiguous responses fail conservatively.

The PA keeps the existing authorization predicate. Its added reason labeling reports current `revoked`/`suspended` state when that state changed after the separate credential-validation RPC. Thus a genuine revoked-state denial no longer misleadingly reports stale `valid`; a suspension is a policy failure, not an expiry event. Scope, approval, workflow totals and actual permissions are unchanged. Existing research traces retain their original labels and require the separately documented endpoint adjudication.

Independent review found no blocking defect in this prospective path. The14 focused offline cases in `tests/test_probe.py` and `tests/test_service_failures.py` passed on23October2026 in0.37seconds. These are mocks, not proof of the deployed client/runner path. No rebuild or live verification was performed for this review. The source-image test must subsequently include the new `probe.py` and other current modules; the presently deployed image is intentionally still the original research image.
