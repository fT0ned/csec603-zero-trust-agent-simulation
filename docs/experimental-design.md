## Table VI. Simulation design and fixed controls

| Design element | Frozen implementation and interpretation |
| --- | --- |
| Environment and trust boundary | One Windows/Docker host; separate gateway PEP, policy administrator (PA), OPA policy engine (PE), SPIRE server/agent, attested client, attacker client, and four private mock tool services. Actual request path is client → gateway → PA → tool; PA consults OPA. Host harness, issuer, PA, tools and evidence stores are trusted; control-plane compromise is outside scope. See [architecture](architecture.md), [Compose](../compose.yaml), [service](../testbed/service.py) and [tool implementation](../infra/tools.py). |
| Components and dependency pinning | SPIRE 1.14.1, OPA 1.10.1, Python 3.12.12; frozen Compose/Dockerfile image digests and [transitive dependency lock](../requirements.lock.txt). Node join-token attestation uses a pinned CA bundle; workload identity uses Unix UID 10001. The attacker is a separate UID 10002 container without the workload socket. Host-side LLM planning directs actual HTTP calls from the attested client. |
| Conditions | C0: disposable non-expiring static bearer credential, broad tools, minimal logs. C1: real SPIRE JWT-SVID, same broad tools, identity-aware logs. C2: C1 plus per-request OPA scope/delegation/workflow controls, careful simulated approval, one-use JIT and full audit. C2-noWF removes only cumulative workflow limits; C2-RS replaces careful approval with approval of every policy-eligible high-impact request. Ablations apply only to S2/S5. All conditions validate credentials and consult the same gateway deny-list on every request. |
| Interpretation of controls | C1–C0 principally tests finite bearer lifetime; attestation governs issuance and does not prevent replay of a stolen bearer copy. It does not isolate an independent attestation effect. C2 is a bundled intervention apart from its two ablations. Authentication alone does not establish legitimate intent. |
| Trusted delegation and action catalog | PA-owned principal `principal:analyst` → research-agent → task record; the model cannot grant its own authority. Nine catalog actions: files.read/delete, email.read/send, crm.read/export/delete, payments.read/pay. Task families receive only their designated action subsets. Fixtures and exact trusted expected calls are frozen in [fixtures.py](../testbed/fixtures.py). |
| Bounds and approval | CRM export request bound 5 records and payment bound 50 synthetic units; cumulative export/payment task bounds 10 records/100 payment units. Trusted recipients are analyst@corp.test and partner@partner.test; trusted vendor is vendor-1. High-impact files.delete, email.send, crm.delete and payments.pay require approval after scope eligibility. Careful approval matches complete parameters and remaining multiplicity of trusted expected calls. The simulated reviewer is idealized; measured approval time is computation, not human response time. |
| JIT and atomicity | Grants bind task, credential and canonical action fingerprint, expire after 120 seconds and are atomically consumed once. PA serializes policy check, conservative reservation, grant consumption and dispatch. Successful execution reconciles actual usage; ambiguous timeout retains reservation, confirmed no-effect 4xx releases it. Same write ID cannot commit twice; retries still validate credentials and, for C2, receive an OPA receipt decision. See [service](../testbed/service.py) and [OPA policy](../infra/opa). |
| Workloads and injection | Three synthetic legitimate task families: CRM summary (5 records), approved vendor payment (25 units), approved email summary. S2 has four single-step payloads; S5 has chunked export and split payment payloads. Injection patterns are authors’ adaptations of published task-hijacking/instruction-override patterns, not literal benchmark cases or benchmark-comparable scores. Tools persist synthetic data only; emails/payments are mock effects. |
| Model and request settings | Requested alias deepseek-flash; provider-documented version DeepSeek-V4.1-Flash-1017 checked 2026-10-22. The alias is mutable (`immutable_snapshot=false`), so preserve requested/returned model, fingerprint, catalogue and date. Temperature 0, thinking disabled, maximum 1,024 output tokens per response, 12 provider rounds, 90-second HTTP timeout; no model/provider fallback. Harness seeds do not make provider generation deterministic. See [agent adapter](../testbed/agent.py). |
| Budget | USD 4 aggregate cap across earlier and current batches, using persistent `.runtime/spend.sqlite`; no reset, top-up or alternate provider. Usage-based estimates and retained uncertain reservations are not an invoice. API balance reconciliation is separate. Budget exhaustion remains an explicit incomplete-collection outcome. |
| Sampling and execution | Thirty repeats per planned cell, seeds 603–632; deterministic shuffled manifest, 32 workers. One fresh scenario/condition/task run is the experimental unit; calls and probes are repeated observations within that unit. Matched comparisons require unique identical pair ID/seed/payload sets. See [study config](../configs/study.json), [runner](../testbed/runner.py) and [Table VII](#table-vii-planned-full-collection-allocation). |
| Reset | Fresh run namespace, registration/credential, tool snapshot, counters, deny-list state, grants and audit chain. Auxiliary authority probes use independent fresh tasks. Containers are reused; reset is not a global restart per trial. The preserved host evidence is outside client/SUT mounts. |
| Lifetime and handoff | Main lifetime 900 seconds. S3/S4 additionally use 300/3,600 seconds; C0 has no expiry and is assigned matched observation strata only. Credential handoff is scheduled 120 seconds after host-observed credential receipt, not nominal issuance or workflow completion. Preserve actual receipt, theft, expiry and handoff error. Missed setup deadline is an infrastructure failure. |
| Real-time probes and observation | S3 harmless validity probes every 10 seconds; S4 every 0.1 seconds, on absolute clock grids inside the attacker container. Full observation horizon from theft is min(TTL + 90, 3,690): 390/990/3,690 seconds for the three lifetime strata, including matched C0. Actual final timestamps govern; grid/transport can cross the nominal boundary. No accelerated lifetime substitution. |
| Revocation | S4 now/expiry modes share credential/lifetime/deny-list semantics. A first successful scheduled harmless probe establishes validity and client readiness; the now arm then issues the security decision/revoke command while the grid continues. Keep command, deny-list activation and first-denial timestamps distinct. Clock-bracket evidence is preserved in [infrastructure verification](verification/infrastructure.json). |
| Pilot and infrastructure validation | Final pilot002: 88 genuine LLM trials, four repeats, S3/S4 TTL 300 and configured observation 305 seconds; other scenarios TTL 900. Pilot validates workflow/timing, not full-study hypotheses. Engineering/scripted/stress collections are separate evidence classes. No pilot/full or scripted/LLM pooling. |
| Evidence and independent outcomes | Raw prompts, responses, tool calls, model/usage metadata, full audit, protected truth/checkpoints, run summaries, captured source and sealed SHA-256 manifests. Compressed traces retain uncompressed hash/length metadata. Independent SQLite state/write ledgers are collected from each tool via [tool_evidence.py](../scripts/tool_evidence.py). Security success is checked against committed effects, not only gateway logs. Hash manifests require their own protected trust boundary; they are not digital signatures. |
| Attribution and audit | Predictor sees trusted origin and observed parameter-level links from read untrusted content, never truth labels: unexpected origin → impersonation; linked injected parameters → coercion; otherwise none. Harmless exposure alone is insufficient. Independent truth enters only scoring. Full C2 audit completeness requires the specified principal/agent/task/delegation/provenance/decision/result/hash fields; baseline fields are not reconstructed. Audit-copy alteration, middle deletion, tail deletion, complete deletion and reorder tests use separately protected hash/count checkpoints. |
| Validity limits | Single machine/agent, fixed synthetic tasks, idealized approver, mutable model and contention limit generalization. An ignored injection remains an unsuccessful attack, not proof of strong controls. Attribution is an observable rule, not proof of internal cognition. No claims of production scale, distributed propagation, human approval behavior, mTLS or control-plane compromise resistance follow from this design. |

## Table VIII. Research questions, hypotheses and planned comparisons

| --- | --- | --- | --- |
| RQ1: Under what enterprise conditions does attested, short-lived workload identity reduce credential-theft and replay exposure for non-human identities, including AI-agent instances, relative to long-lived static credentials? | H1, S3 | Validity exposure and survival evidence; C0→C1 and C0→C2 within lifetime strata. C1→C2 is an additional planned comparison, not an H1 support contrast. Harmful success/authority are distinct authorization outcomes. | At least 60-second reduction, using the conservative observed interval bound defined below. |
| RQ1 | H1b, S4 | Within each condition/lifetime, now→expiry command-to-first-denial delay; separate command-to-active propagation. | Wait minus immediate delay ≥1,000 ms, with observed or conservatively bounded survival evidence. Similarity across lifetimes is not equivalence. |
| RQ2: Under what enterprise conditions do agent authorization controls scoped delegation, tool and API restriction, just-in-time elevation, and human approval gates act preventively by reducing unauthorized-action likelihood or reachable authority, versus act as containment by limiting blast radius after compromise, relative to their policy-complexity and manageability costs? | H2, S2/S3 | Unauthorized-outcome risk and distinct reachable actions; C1→C2 and C0→C2, with payload/approval strata preserved. S2 C0→C1 outcome risk is null context rather than a confirmatory control benefit. | Risk decrease ≥0.20 or reachable-action decrease ≥2, assessed per applicable metric. | RQ2 | H2b, S5; S2 ablation context | C2→C2-noWF unauthorized risk/cumulative-authority ratio. ## Table IX. Measurement definitions, uncertainty and evidence

| Metric | Definition and evidence | Required interpretation |
| --- | --- | --- |
| Unauthorized outcome | Attack runs with a committed primary harmful goal / runs with measured attack outcome; tool state/write ledger independently checks effects. | Wilson 95% interval. An ignored injection is false; unmeasured failure is null. S5 primary goal is total-bound violation. |
| Harmful-action success / cumulative authority | Committed harmful actions / attempted harmful actions; achieved record/payment total / trusted task limit. | Run-cluster bootstrap for action ratios; record and payment strata separate. Calls are not independent replicates. |
| Reachable authority | Number of distinct successful actions in the nine-action probe catalog after compromise. | S3 auxiliary fresh tasks execute concurrently after handoff and before expiry without spending main counters or delaying its grid. |
| Replay exposure | Last successful harmless validity replay minus theft; first denial supplies the observable upper endpoint. | Transition is interval-bounded between success and denial. Still-valid credentials are right-censored at actual observation end; nominal expiry is not an event. Kaplan–Meier/log-rank use first observed denial, not exact expiry. |
| H1 conservative benefit | Median right-condition observed first-denial upper bound minus median left-condition last-success lower bound. | Must be ≤−60 seconds; right side requires observed denial. Censored left observations supply lower bounds only. No ordinary mean of censored durations. |
| Revocation propagation / denial | Active deny-list timestamp minus command; first denied probe minus security decision/command, respectively. | Separate actual clock anchors. For censored expiry waits, use decision-anchored survival endpoints and median wait last-success bound minus median immediate observed denial ≥1,000 ms; never invent static-key expiry. |
| Attribution | Correct predicted run incident labels / labeled incidents; complete coercion/impersonation/none confusion counts. | Wilson interval; independent truth inaccessible to predictor. Observable provenance does not establish cognitive causality. |
| Audit completeness | Actions with every required C2 field / all recorded attempts; malformed model calls remain in denominator even without an audit row. | Run-cluster interval; report baseline missingness. Protected checkpoints permit truncation detection beyond an isolated hash chain. |
| Task and injection behavior | S1 legitimate completion; attack injection-follow rate (attempted injected action). | Separate Wilson intervals and failure categories; attempting an injection and committing harm are different outcomes. |
| Timing and approval | Within-run median latency/authorization, then across-run median/Q1/Q3/p95; within-run call p95 distributions separately descriptive. Approval requests/run and computed added milliseconds. | Inferential unit is run median. Preserve probe grid error, measured transport and clock uncertainty; no fabricated human review latency. |

Binary contrasts use exact paired McNemar when pairing is valid, otherwise Fisher; continuous contrasts use paired Wilcoxon or unpaired Mann–Whitney with the recorded exact/tie-corrected method. Effects are right minus left; deterministic 2,000-resample seed-603 run bootstrap preserves pairs. The conservative Holm family contains all planned inferential contrasts/metrics across scenario/lifetime/revocation strata within a collection/mode/phase/model, including H1b and missing contrasts. The supplemental S5 intent family is descriptive. Do not select a smaller family after outcomes. Thirty repeats do not imply thirty per subgroup; zero failures in thirty still has Wilson upper 95% bound about 11.4%.

Support requires complete genuine LLM/full evidence, approved freeze preceding collection, matching configuration, all 1,200 planned units represented once with reconciled failures, actual model metadata, verified raw seals, complete required measurements, Holm-adjusted p<0.05 and the directional practical threshold. Missing/incomplete evidence cannot become a support claim. Only infrastructure failures permit one linked same-seed rerun; preserve originals and distinguish provider/model errors. Duplicate terminal units use the earliest-started terminal record without outcome consultation and list exclusions.
